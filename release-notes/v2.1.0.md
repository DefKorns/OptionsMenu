## Options Menu v2.1.0

- **Menu language follows the console:** Language → Options Menu language now defaults to *Automatic*, which uses the console's own language. Pick a language there to override it.
- **Clearer confirmations:** non-destructive actions confirm with **A**; deleting or overwriting still needs **Start+Select**. Save Manager and Module Uninstaller dialogs share the same look.
- **Save Manager:** saves of games with the same name are tagged with their game code, and empty saves are hidden.
- **Downloads:** add-ons can show a download screen with a progress bar and the free space left, and the file being downloaded is shown by its name only (`2ks_star_wars` instead of `SNES.2ks_star_wars.tar.g`).
- **Waiting screens:** add-ons can show their "please wait" messages with a moving bar, and reloading the Home menu shows it instead of a black screen.
- **More robust:** if the menu is closed by the system (SIGTERM/SIGHUP), the console's UI comes back instead of staying paused. Scripts started from the menu no longer hold the screen, so `chmenu` and folder switches don't kill them halfway.

## Why 2.1.0

This release adds features without breaking anything that already works, so it's a minor version bump (2.0.0 → 2.1.0), not a patch:

- **New for add-ons:** the `DOWNLOAD` and `CHOICE` command types, the `DELETE_BLOCKED_KEY` dialog, and new `om_functions` helpers (`omSplash`, `omLoading`, `omUnpack`, `omReloadMenu`, `omReloadMenuLater`, `omLangCode`, `omLangList`). Add-ons that use them need 2.1.0 or newer: **Theme Selector 3**, **Console Language** and **Favorites Manager** do.
- **Nothing removed for installed add-ons:** command files and the `om_functions` helpers from 2.0.0 work as before, so add-ons made for 2.0.0 keep working.
- **For C++ add-on developers:** the framework grew `ScreenChrome`, `PanelDialog`, `NoteBox`, list-row and text-layout helpers, and `close_on_exec`. `ModernChrome` is gone (use `ScreenChrome`) and the code builds with `-std=c++14`. Add-ons compile the framework in, so this only matters when you update your `vendor/OptionsMenu`.

## Which file?

- `options_menu.hmod`: use this one.
- `options_menu_compat.hmod`: only if another hmod replaces the console's `libstdc++` (e.g. RetroArch 1.8.4 Xtreme SC) and the menu doesn't open with the normal build.
